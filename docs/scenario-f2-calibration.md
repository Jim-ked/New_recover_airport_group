# 场景级 F2 校准覆盖

情境没有通用扩展字段。F2 覆盖使用服务器本地 JSON 文件，不新增数据库字段。

## 文件位置与格式

在当前数据库同目录放置 `<数据库完整文件名>.f2-calibration.json`：

- `foo.sqlite3` 对应 `foo.sqlite3.f2-calibration.json`。
- `foo.db` 对应 `foo.db.f2-calibration.json`，与前者独立。
- 根对象按数据库内已保存的 `situation_id` 区分情境。
- 支持 UTF-8 和带 BOM 的 UTF-8。

下面只演示结构，数值不是福建场景的正式标定；实际两张表须覆盖该情境任务机型所有正消耗资源：

```json
{
  "SCN_EXAMPLE": {
    "f2_resource_reference_quantities": {"RS001": 10000.0},
    "f2_resource_weights": {"RS001": 1.0}
  }
}
```

参考量单位应与对应资源的消耗量单位一致；不进行资源 ID 映射或单位转换。
迁移场景数据库时，同时复制对应 JSON，并保留情境 ID。

## 生效规则

校验运行条件和提交运行共用 `RunSnapshotService.build_snapshot()`：

1. 根据当前数据库路径和已保存情境 ID 读取配置。
2. 文件不存在或没有该情境条目：继续使用原 `research_objective_v1` 解析行为。
3. 存在条目：两张 F2 表整体替换默认及客户端 F2 表，不合并；其他配置保持原处理。
4. 继续通过 `RunConfig` 校验并冻结到快照。F2 公式、资源模型及 API 协议不变。

条目只能包含上述两个字段，必须同时提供非空对象。数值须为有限正数，两张表资源 ID
集合须相同，并覆盖实际使用资源。无效 JSON、不可读取文件、无效根对象或选中条目、
缺字段及其他校验错误均报运行校验错误，不会静默退回默认配置。

生效校准纳入现有输入指纹。校验后改变生效值，使用旧指纹提交会要求重新校验。
历史 Run 及从冻结快照重试的 Run 继续使用快照里的原值，不重新读取 JSON。
本实现不自动生成场景校准文件，也不提供福建场景的正式标定数值。
